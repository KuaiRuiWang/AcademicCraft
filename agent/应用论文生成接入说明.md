# 应用论文生成接入说明

创建应用时勾选“同时生成毕业论文初稿”，并可填写论文题目。代码保存或构建成功后，后台依据实际生成目录冻结资料并逐章写作。在应用对话页的“论文初稿”页签查看进度、编辑章节、重试未完成章节及下载 Word。

## 启用

1. 在现有 MySQL 数据库执行一次 `sql/upgrade_thesis.sql`，再启动新版本后端。新数据库使用 `sql/init.sql`，无需重复执行升级脚本。
2. 后端使用 JDK 21；论文内容调用已有 `openAiChatModel`，无需另配模型账户。
3. 安装 Word 导出工具（Python 3.10+，Node.js 22+）：

   ```powershell
   python -m venv tools/thesis/.venv
   tools/thesis/.venv/Scripts/python.exe -m pip install -r tools/thesis/requirements.txt
   npm ci --prefix tools/thesis
   ```

   Linux 的 Python 位于 `tools/thesis/.venv/bin/python`。Mermaid 安装过程会下载 Chromium；已有 Chrome 时可设 `PUPPETEER_SKIP_DOWNLOAD=true` 跳过下载，并用 `PUPPETEER_EXECUTABLE_PATH` 指定浏览器可执行文件。服务器需要安装中文字体，例如 Noto Sans CJK。

4. 应用优先使用本地 `tools/thesis/.venv`。独立部署 jar 时，指定 `--thesis.python-command=/绝对路径/venv/bin/python` 和 `--thesis.mermaid-cli=/绝对路径/node_modules/@mermaid-js/mermaid-cli/src/cli.js`。Python 排版脚本、来源说明和上游许可证已包含在 jar 资源中；Python/Node/Chromium 运行环境需随部署准备。
5. 前端照常执行 `npm run build`。旧应用也可在论文页签手动开始生成，不要求重新创建应用。

## 内容和任务行为

- 默认生成中英文摘要、绪论、相关技术、需求分析、系统设计、系统实现、系统测试、总结与展望、参考文献与待补材料，共 10 节。
- 数据来自生成应用的 `.vue`、JavaScript、接口契约、数据模型等实际文件。依赖、构建产物、隐藏文件和 `.env` 不进入资料；冻结材料保存在 `tmp/thesis/{appId}/{sourceVersion}/source-context.txt`，任务也保存相同资料。
- 每章单独保存。模型中断后保留完成章节，重试只继续未完成章节；代码版本变化时重新生成未被手动编辑的章节。手动编辑章节保留原文并提示核对。
- 修改代码前会撤销旧论文任务的版本，旧模型响应无法覆盖新任务。编辑正文也会校验版本与原文，避免多窗口覆盖。
- 任务与 SSE 连接分开，后端重启后恢复 `generating` 状态任务。当前按单后端实例部署恢复任务；多实例部署前需增加任务租约。
- 静态源码不是实际测试记录。没有运行证据时，测试结果标记“待验证”；真实截图、经核验文献和学校模板需补充。全栈修改流程原本不重新构建，因此新稿不会宣称修改后的应用已通过构建或运行验收。
- Word 使用 A4 和通用中文论文样式，含图片、表格、原生标题、页码和目录域。目录可在 Word 打开后更新，最终校级排版仍以实际学校模板为准。
- 系统设计章节最多导出 8 张 Mermaid 图，仅接受本地文字与图形，不加载外部图片、链接或图内配置指令。图表语法或依赖错误时导出明确失败，不返回缺图的半成品。

## 验证

```powershell
mvn -Dtest=ThesisServiceTest,ProjectSnapshotServiceTest,ThesisWriterTest test
tools/thesis/.venv/Scripts/python.exe -m unittest discover -s tools/thesis/tests -v
```

前端回归脚本使用隔离的 HTTP 测试接口，不连接真实用户数据库：先以 `VITE_API_BASE_URL=http://127.0.0.1:18723/api` 启动 Vite（`--host 127.0.0.1 --port 5179`），再于前端目录执行 `node tests/thesisPanel.browser.mjs`。浏览器需要 Chromium 缓存或 `PUPPETEER_EXECUTABLE_PATH`。
